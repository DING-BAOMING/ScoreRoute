# Security Policy

## 报告安全漏洞

我们非常重视安全问题。如果您发现安全漏洞，请通过以下方式报告：

### 报告方式

1. **不要** 在公开 Issue 中报告安全问题
2. 发送邮件至项目维护者（通过 GitHub 私信）
3. 或使用 GitHub 的 [Private vulnerability reporting](https://github.com/DING-BAOMING/ScoreRoute/security/advisories/new)

### 报告内容

请包含以下信息：
- 问题描述
- 重现步骤
- 潜在影响
- 建议的修复方案（如果有）

### 响应时间

- 我们会在 24-48 小时内确认收到报告
- 初步评估后会在 7 天内给出详细回复
- 根据问题严重程度决定修复时间线

### 严重等级

| 等级 | 定义 | 修复时间 |
|------|------|---------|
| Critical | 远程代码执行、数据泄露 | 24-72 小时 |
| High | 认证绕过、敏感信息暴露 | 1-2 周 |
| Medium | 功能缺陷、拒绝服务 | 2-4 周 |
| Low | 极小影响、边缘情况 | 下一个版本 |

## 安全最佳实践

### 部署时

- 务必更改默认的 `ADMIN_PASSWORD`
- 务必设置强壮的 `JWT_SECRET`
- 使用 HTTPS 终结点
- 限制数据库文件权限

### 运行时

- 定期更新到最新版本
- 监控日志中的异常访问
- 使用防火墙限制暴露端口
