# 系统架构

## 技术栈

| 层级 | 技术 |
|------|------|
| 后端 | Go + Gin + SQLite |
| 前端 | Vue3 + Element Plus |
| 部署 | Docker |

## 核心模块

| 模块 | 职责 |
|------|------|
| Proxy Handler | 处理/v1/*请求，验证Token，路由分发 |
| Dispatcher | 根据评分选择最优模型，处理轮询逻辑 |
| Scheduler | 定时任务：自动重启用过期禁用项 |
| Repository | 数据库访问层，处理CRUD操作 |

## 评分算法

### 7因子权重

| 指标 | 权重 | 新模型默认 | 说明 |
|------|------|-----------|------|
| 成功率 | 10% | 85% | 成功请求占总请求比例 |
| 延迟分数 | 10% | 85 | 延迟越低分数越高 (阈值30秒) |
| 稳定性 | 10% | 85 | 基于样本量，样本越多越可靠 |
| 用户评分 | 20% | 85 | 用户1-100评分 |
| 样本评分 | 30% | 85 | 样本分析自动评分 |
| 成本评分 | 10% | 50 | 基于API成本 |
| 时间评分 | 10% | 70 | 基于模型过期时间 |

### 计算公式

```
Score = 成功率×0.10 + 延迟分×0.10 + 稳定性×0.10 
      + 用户评分×0.20 + 样本评分×0.30 + 成本评分×0.10 
      + 时间评分×0.10 + 奖励 + 惩罚
```

### 奖励/惩罚机制

| 类型 | 规则 |
|------|------|
| 奖励 | +N分(新模型)，24小时衰减 |
| 惩罚 | -N分(每次成功调用)，每调用+1恢复 |
| 删除 | 惩罚低于0分自动删除 |

追踪键: `渠道_格式_类型_模型名`

### 新模型默认分数

尚未被调用过的新模型 (total_calls = 0)：
- 成功率: 85%
- 延迟分数: 85
- 稳定性: 85
- 样本评分: 85

## 轮询机制

### 轮询策略

- **方式**: 渠道优先 + 模型次之
- **排序**: 按调用次数(call_count)升序

### 模型名称行为

| 模型名称 | 行为 |
|---------|------|
| `auto` | 按Token的format+type轮询 |
| `AUTO` / `POLL_ALL` | 轮询所有模型 |
| `__POLL_ALL__` | 轮询所有模型 |
| `__AUTO__` | 按format+type轮询 |
| 具体模型名 | 使用指定模型 |

### 轮询流程

```
请求 → Token验证 → 选择渠道(call_count最小) 
       → 选择模型(call_count最小) → 上游API
       → 更新call_count → 记录日志
```

## 自动禁用规则

| 限制类型 | 禁用范围 | 自动重启用 |
|---------|---------|----------|
| Token速率限制 | 仅Token | ✅ |
| Token总Token限制 | 仅Token | ❌ |
| 模型速率限制 | 仅该模型 | ✅ |
| 渠道速率限制 | 仅该渠道 | ✅ |

## 数据流

```
请求 → Proxy → Token验证 → Dispatcher → 评分选择 → 上游API
                                                      ↓
响应 ← Proxy ← Token/模型更新 ← 日志记录 ←
```
